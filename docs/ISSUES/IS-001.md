# Issue

### What?

IS-001: Scaffold the VS Code extension foundation.

This issue adds the first runnable VS Code extension slice for Branch Diff Review: extension packaging, activation, the **Open Branch Diff Review** command, a placeholder Branch Diff sidebar view, a placeholder review panel in the editor area, and a React/Tailwind webview asset build path. It intentionally stops before any Git repository discovery, branch detection, or patch rendering logic.

- [x] Running the extension in VS Code exposes the command in the command palette.
- [x] Invoking the command opens a placeholder Branch Diff Review diff panel in the main editor area.
- [x] The Activity Bar or sidebar contribution exposes a placeholder Branch Diff view.
- [x] The placeholder UI clearly represents the future base/compare/sidebar/diff-panel surfaces without performing Git work.
- [x] The scaffold has deterministic build/typecheck/check commands documented in the issue recap.
- [x] No Git comparison, branch detection, or patch parsing behavior is implemented in this issue.
- [x] Relevant checks pass.

### Notes

- Scope is intentionally limited to extension scaffolding and placeholder review surfaces.
- The sidebar and panel use bundled local React webview assets and Tailwind CSS built into `dist/webview`.
- The Branch Diff sidebar is explicitly contributed as a webview, and both surfaces are rendered by dedicated React components mounted by small webview entrypoints.
- Webview HTML shows a startup status and replaces it with actionable error details if the bundle fails to load, React fails before mounting, or a component throws while rendering.
- Biome provides the scaffold's lint and format check.
- The existing hook now runs `pnpm check` at the repository root because the scaffold lives at the root rather than in a `frontend` subdirectory.
- Follow-up issues should add the internal Git backend, real branch selection, changed-file data, and selected-file patch rendering.

# Issue recap

This recap is committed to version control and supplies the pull request description.

# What has been built

The repository now contains a minimal VS Code extension package with TypeScript source files, extension contributions, and a launch configuration for running the extension host from this workspace. Activating the extension contributes the **Open Branch Diff Review** command and a dedicated **Branch Diff** Activity Bar container with a webview-backed sidebar.

Running the command opens a placeholder **Branch Diff Review** webview panel in the editor area. The sidebar and panel both describe the future base branch selector, compare branch selector, changed files area, and selected diff area while clearly stating that Git-backed behavior is deferred. The sidebar contribution is declared as a webview, and dedicated React components render both surfaces through bundled entrypoints permitted by the webview content security policy.

A small build path now exists for webview assets. Extension code compiles with `tsc`, and the sidebar and diff-panel React entrypoints are bundled into `dist/webview` with a lightweight `esbuild` script. Tailwind compiles the webview stylesheets, and Biome checks formatting/linting. The repository also includes deterministic `pnpm typecheck`, `pnpm lint`, `pnpm build`, and `pnpm check` scripts.

### Architectural alignment

The implementation matches the foundation-only scope from `docs/SPEC.md`: it creates the shell that later issues can build on without introducing premature Git backend abstractions, fake diff data, or branch comparison logic.

### What is left

Later issues still need to add repository detection, current branch and base branch discovery, merge-base comparison logic, changed-file summaries, file selection behavior, and actual diff rendering. This issue does not load repository state, parse patches, or display any real file changes.

# Problems found

- During manual testing, the Branch Diff sidebar first rendered as a tree view with no data provider because the contributed view was not marked as a webview.
- After correcting the contribution type, the content security policy also needed to permit the bundled local scripts.
- The first component build still emitted classic `React.createElement` calls without importing a `React` value, causing both bundles to throw before mounting and leaving empty webview roots.
- The fix declares the sidebar view as a webview, permits its local bundled script, builds JSX with React's automatic runtime, mounts dedicated React components, and reports startup or render failures inside the affected webview.
