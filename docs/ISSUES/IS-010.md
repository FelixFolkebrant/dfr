# Issue

### What?

IS-010: Redesign the Branch Diff sidebar around branch and commit review.

Replace the current labeled base/compare layout with a compact, theme-aware sidebar that defaults to reviewing the active branch against `main`, supports stepping through each commit or the full branch diff, exposes collapsible commit and issue-documentation details, and moves base-branch selection into a focused settings view.

### Acceptance criteria

#### Sidebar layout and branch selection

- [x] Remove the redundant **Merge-base comparison**, **Branch changes**, **Base**, and **Compare** headings from the normal review view.
- [x] Show one prominent branch control at the top of the sidebar, following the supplied rough layout and using VS Code theme colors, typography, borders, focus styles, and icons.
- [x] Default the reviewed branch to the active local branch and the comparison base to `main` when no preferred base is configured; retain the existing configured-base and missing-`main` fallback behavior.
- [x] Opening the branch control lists the available branches and selecting one reloads the review against the current base.
- [x] Branch and commit controls share the same theme-aware dropdown list while retaining their distinct bordered and borderless triggers; branch lists remain searchable while commit lists keep **All** pinned at the top.
- [x] The active local branch remains pinned below the branch search field while other matching branches scroll independently.
- [x] Keep remote branches folded below local branches by default, while revealing them when searched or selected.
- [x] Keep the existing changed-file tree below the redesigned summary. Its files, statuses, line counts, and selected-file diff must always reflect the currently selected **All** or commit scope.
- [x] Keep the branch, commit, documentation, and summary controls fixed while only the changed-file tree scrolls.
- [x] Present the aggregate summary in one compact line, for example `4 files +100 -241`, without repeating explanatory labels.

#### Commit navigation and diff scopes

- [x] Discover the commits introduced by the reviewed branch using the same merge base as the full branch comparison.
- [x] Provide an **All** scope plus every introduced commit, ordered from oldest to newest for sequential review.
- [x] Show the selected commit's abbreviated SHA, position, and previous/next arrow buttons.
- [x] Show the selected commit's position, such as `1/5`, at a readable size immediately to the right of the left-aligned commit control.
- [x] Opening the commit control displays **All** and each branch commit using the configured naming format; positional counts stay out of the picker.
- [x] Let the reviewer show hashes, hashes with commit titles, or commit titles in both the commit control and its dropdown.
- [x] Number commit dropdown rows in review order, for example `1. e138d7 GL-008: Commit message`, with the hash muted relative to the title and without switching to monospace type.
- [x] Provide a copy action for the full hash of the selected commit and disable it for **All**.
- [x] Selecting **All** shows the complete merge-base-to-reviewed-branch diff.
- [x] Selecting a commit shows exactly that commit's first-parent diff and updates the changed-file tree, totals, file contents, and binary/rename states to that scope.
- [x] Previous and next move one commit at a time, cannot move beyond the first or last commit, and expose their disabled state visually and to assistive technology.
- [x] Loading a new branch, base, or commit scope invalidates superseded summary and file requests so stale results cannot replace the current selection.
- [x] A branch with no introduced commits presents an actionable empty state while keeping branch selection and settings available.

#### Commit message and related documentation

- [x] Show a collapsible **Message** section for a selected commit; its collapsed state shows a single-line subject preview and its expanded state reveals the complete subject and body without changing typography.
- [x] Hide or clearly mark the **Message** section as unavailable when **All** is selected rather than displaying a misleading commit message.
- [x] Show a collapsible **Docs** section containing repository-tracked Markdown files related to the reviewed issue.
- [x] Extract issue keys from the reviewed branch name and commit subjects using boundary-aware forms such as `#1`, `GH-1`, `GH-001`, `GL-001`, and `IS-001`.
- [x] Normalize matching case and numeric zero-padding while preserving the namespace: `GH-1` matches a filename beginning `GH-001`, but does not match `GL-001`; `#1` does not match every prefixed issue numbered 1.
- [x] Match only Markdown basenames that begin with an extracted issue key followed by the end of the basename or a separator. Do not use loose numeric or substring matching.
- [x] Prefer an issue key found in the branch name, then include keys found in branch commit subjects; remove duplicate document results and sort them consistently.
- [x] Selecting a document opens that Markdown file in the editor.
- [x] When no key or related document is found, show a compact empty state instead of hiding a detection failure or listing unrelated Markdown files.

#### Settings, states, and accessibility

- [x] The cog in the branch control toggles a settings view matching the supplied rough layout.
- [x] The settings view contains the **Compare with** base-branch control and commit-naming preference; selecting a base immediately reloads the current review and returning to the review preserves both choices.
- [x] Keep the settings structure suitable for adding later options without adding speculative settings or configuration in this issue.
- [x] Preserve actionable loading and Git error states for branch, commit, documentation, summary, and selected-file operations.
- [x] All controls have accessible names, non-outline keyboard states, correct expanded/selected/disabled semantics, and work with Enter, Space, Escape, and arrow keys where appropriate.
- [x] The layout remains usable without horizontal scrolling in a narrow VS Code sidebar; long branch names, SHAs, subjects, messages, and document names truncate or wrap according to their content role.
- [x] Focused tests cover issue-key normalization and matching, commit discovery/order, All versus commit diff ranges, navigation boundaries, stale-request handling, and sidebar messages; all repository checks pass.
- [x] Implement component styling with Tailwind utilities; keep the sidebar stylesheet limited to Tailwind directives and use an inline value only for dynamic tree-depth indentation.
- [x] Reduce folder-name opacity so changed files carry more visual emphasis.
- [x] Show status icons only for added and deleted files; modified, renamed, and unknown files use the default unmarked appearance.

### Notes

- The supplied images are directional wireframes. Preserve the current theme integration rather than copying fixed colors or pixel dimensions.
- **All** means the aggregate branch comparison from merge base to reviewed branch. It does not add a new combined all-files editor; file rows continue to open VS Code's native per-file diff editor.
- A selected commit uses first-parent semantics, equivalent to `git diff <commit>^1 <commit>`. This keeps merge-commit behavior deterministic and aligned with the change introduced by that commit on the reviewed branch.
- Documentation discovery is local and repository-based. GitHub/GitLab APIs, issue tracker lookups, fuzzy semantic matching, and untracked Markdown files are out of scope.
- Persisting branch, base, commit, disclosure, or settings state across VS Code sessions is out of scope.
- Persisting the commit-naming preference, changing Git configuration, and redesigning the native diff editor are out of scope.

# Issue recap

# What has been built

The Branch Diff sidebar now centers the reviewed branch in one compact control and moves base selection and commit naming into a cog-opened settings view. Branch and commit selection share one theme-aware dropdown list without forcing their triggers to match. The shared dropdown grows to use wider and taller sidebars, remains within narrow viewports, and wraps long branch names and commit titles. Branch lists remain searchable with the active local branch pinned below the search field and remote branches folded into a separate disclosure; searching or selecting a remote branch reveals that group. Commit lists omit search and pin **All** instead. Commit entries and the trigger can show their hash, title, or both. Dropdown commit rows are numbered in review order and visually de-emphasize hashes relative to titles. The selected position remains immediately to the right of the left-aligned commit control, followed by a full-hash copy action. Focus uses subtle component background states without the bright outline. Expanded commit messages retain the preview typography and simply reveal more content. The branch, commit, documentation, and summary controls remain fixed while only the changed-file tree scrolls. Folder names are visually muted, and only added or deleted files receive status icons.

The Git backend discovers branch commits from the merge-base range in oldest-first topological order. **All** retains the branch-wide merge-base comparison; selecting a commit uses its first parent and SHA as the exact diff endpoints. Scope changes update file statuses, totals, contents, rename/binary handling, and native diff tabs while request sequencing prevents stale summaries or files from replacing newer selections.

Related Markdown files are discovered from tracked repository files. Branch names and commit subjects contribute boundary-aware issue keys; matching normalizes case and zero-padding while keeping `#`, `GH`, `GL`, `IS`, and other namespaces distinct. Listed documents open directly in the editor.

### Architectural alignment

| Area | Implementation |
| --- | --- |
| Git backend | Adds review metadata discovery and explicit diff endpoints without moving Git work into the webview. |
| Controller | Owns All/commit scope state, validation, request invalidation, and selected-file loading. |
| Protocol | Adds validated commit-selection and tracked-document messages. |
| Webview | Renders state and sends user intent; Tailwind utilities own component styling while repository discovery, Git commands, and matching remain in the extension host. |
| Native diff | Reuses the existing lazy per-file VS Code diff editor for branch and commit scopes. |

### What is left

The reviewer must complete the manual appearance, interaction, accessibility, and responsive checks below. Combined all-files editors, external issue APIs, persisted sidebar state, and additional settings remain intentionally out of scope.

# Problems found

### 0. (HIGH) Tailwind grid tracks stretched the sidebar - FIXED

The Tailwind migration combined `min-h-screen` with top-level Grid containers. Grid's default alignment stretched auto-sized rows across the available sidebar height, producing an oversized branch card and large gaps between every review section. The final implementation uses vertical Flexbox containers so each section remains content-sized.

No known implementation problems remain. Manual reviewer judgments are recorded as unchecked confirmation items above.
