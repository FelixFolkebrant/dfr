# Issue

### What?

IS-022: Wait for Git repository discovery during startup.

Delay DFR's initial repository lookup until VS Code's built-in Git extension has completed its initial scan, so opening DFR in a Git workspace works without a manual refresh.

### Acceptance criteria

- [x] DFR waits for the built-in Git API to initialize before reading its repositories.
- [x] An already-initialized Git API continues without registering an unnecessary listener.
- [x] The initialization listener is disposed after the initial scan completes.
- [x] Hiding and reopening DFR retains the rendered sidebar instead of recreating its loading state.
- [x] Automated tests cover delayed and already-complete Git initialization.

### Confirmation

#### Automated checks

- `pnpm check` on 2026-09-08: passed TypeScript checks, Biome, all 7 test files, and production builds.

#### Manual testing

Install the extension from a freshly built VSIX, close VS Code, and open a Git repository in a new VS Code window.

- [ ] **Cold startup:** Open DFR from the Activity Bar immediately after the window appears. Confirm the current repository and branch comparison load without an error notification and without activating **DFR: Refresh**.
- [ ] **Reloaded window:** Run **Developer: Reload Window**, then open DFR. Confirm the same repository and comparison load automatically once Git discovery completes.
- [ ] **Activity tab switching:** After the comparison appears, switch to Explorer or Source Control and then return to DFR. Repeat several times and confirm the existing comparison appears immediately without flashing the loading screen.
- [ ] **Non-Git workspace:** Open a folder that is not a Git repository. Confirm DFR reports that no open Git repository was found after Git discovery finishes.
- [ ] **Manual refresh:** In the Git repository, activate **DFR: Refresh** and confirm the comparison still refreshes normally.

### Notes

- The fix uses the Git API's initialization state, which is set after its initial repository scan, rather than an arbitrary startup delay or retry count.
- The sidebar uses VS Code's retained webview context so its rendered page and local interaction state survive while its Activity Bar view is hidden.
- The unrelated pre-existing deletion of `docs/SPEC.md` is excluded from this issue.
