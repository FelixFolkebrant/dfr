# Issue

### What?

IS-007: Render the selected file diff in the review panel.

This issue connects validated sidebar file selection to lazy patch loading in the extension host and presents the result in the main review panel with `@pierre/diffs`. It includes explicit loading, binary, oversized-patch, empty-selection, and error states while keeping later review controls out of scope.

### Acceptance criteria

- [x] Selecting a file loads only that file's patch through the active merge-base comparison.
- [x] Renamed files include both canonical paths when loading their patch.
- [x] The main panel renders text patches with `@pierre/diffs` and identifies the active branches and file.
- [x] The panel presents clear no-selection, loading, binary, oversized-patch, and error states.
- [x] Patch results from stale comparisons or superseded selections are ignored.
- [x] Patches above a fixed safe rendering limit are not sent to the webview renderer.
- [x] Branch changes clear the previous selected-file presentation.

### Notes

- The existing raw unified patch is passed directly to `PatchDiff`; the webview does not run Git or parse repository state.
- The fixed rendering limit is intentionally internal until product usage justifies configuration.
- `@pierre/diffs` is wrapped by the local diff-panel component so the rest of the extension remains independent of its React API.

# What has been built

Selecting a changed file now starts a lazy patch request through the existing Git backend using the active repository, base branch, compare branch, and canonical path. Renamed files also provide their old path. The controller publishes loading state immediately and rejects results from superseded file requests or comparisons before they can reach the panel.

The review panel now replaces its placeholder with a unified `@pierre/diffs` patch renderer. It identifies the active comparison and selected path, keeps the diff inside a scrollable virtualized surface, and provides dedicated no-selection, loading, binary, oversized-patch, and error states. The panel announces itself when mounted so the extension host can replay the latest state after the webview opens or reloads.

Text patches above the fixed 1 MiB rendering limit are represented by size metadata instead of being posted to the webview. This keeps the initial policy small and deterministic without adding configuration before usage establishes a need for it.
