# Issue

### What?

IS-002: Add Git repository and branch discovery.

This issue adds the extension-host Git foundation needed to identify the repository being reviewed, discover local and remote branches, choose the current branch, and resolve the default base branch before opening Branch Diff Review. It also adds a safe Git CLI runner for later summary and patch work, and uses CLI ref discovery as a fallback when the VS Code Git API returns an incomplete branch list, without computing diffs or sending Git state into the webviews yet.

### Acceptance criteria

- [x] Git behavior is represented by a small internal `GitBackend` interface and stable repository and branch types.
- [x] The built-in VS Code Git extension provides open repositories, the current local branch, and available local and remote branches.
- [x] One repository is selected automatically, the active editor's repository wins when several are open, and otherwise the user is prompted to choose.
- [x] The default base checks the configured branch, `main`, `master`, `origin/main`, and `origin/master` in that order.
- [x] The open command reports actionable errors for no repository, detached HEAD, unavailable Git support, and no default base.
- [x] A successful open identifies the resolved comparison as `<current> into <base>` in the panel title.
- [x] Git CLI execution uses argument arrays rather than shell-interpolated command strings.
- [x] No merge-base, changed-file summary, patch parsing, or webview Git state is implemented in this issue.
- [x] Relevant checks pass.

### Notes

- Repository discovery stays with the VS Code Git API. Branch discovery prefers the API and falls back to Git CLI refs when the extension host does not expose a complete branch list.
- A detached HEAD is rejected because the MVP compares branches and does not yet expose arbitrary commit selection.
- Branch selectors remain placeholders until a later issue adds the extension-to-webview protocol and interactive comparison state.

# What has been built

The extension now has an internal Git backend boundary with repository, branch, and repository-context types. Its VS Code implementation activates the built-in Git extension when needed, discovers open repositories and refs, prefers the repository containing the active editor, and prompts when multiple repositories remain ambiguous.

Opening Branch Diff Review now resolves the current local branch and a default base branch before creating the panel. The configured `branchDiffReview.defaultBaseBranch` setting has first priority, followed by `main`, `master`, `origin/main`, and `origin/master`. Successful resolution is visible in the panel title, while missing repositories, detached HEAD state, unavailable Git support, and missing base refs produce actionable VS Code messages.

A small Git CLI runner executes `git` directly with argument arrays and a bounded output buffer. It is ready for merge-base, summary, and patch commands without exposing shell interpolation or placing Git execution in a webview, and it now also covers branch-ref fallback when the VS Code Git API omits expected refs such as `main` in the Extension Development Host.

## Manual testing

Open this repository in VS Code and launch the `Run Branch Diff Review Extension` debug configuration. Before IS-002, the command opened a generic placeholder panel without inspecting Git state. This issue adds repository and branch resolution before the panel opens.

- [ ] **Launch workspace:** Start the `Run Branch Diff Review Extension` debug configuration from this repository. If VS Code initially creates an empty development host, the extension adds its repository as the workspace folder and reloads the host. Expected result: this repository is loaded in the Explorer instead of showing `No Folder Opened`.
- [ ] **Single repository:** In the Extension Development Host, run **Branch Diff Review: Open Branch Diff Review** from the command palette while this repository is the only open Git repository. Expected result: the panel opens and its editor-tab title reads `<current branch> into main` (or the first available fallback base).
- [ ] **Configured base:** Set `branchDiffReview.defaultBaseBranch` to an existing branch other than the normal default, rerun the command, and inspect the editor-tab title. Expected result: the configured branch is used as the base. Set it to a missing branch and rerun; expected result: the extension falls back through `main`, `master`, `origin/main`, and `origin/master`.
- [ ] **Multiple repositories:** Open a multi-root workspace containing multiple Git repositories, focus a tracked file in one repository, and run the command. Expected result: that file's repository is selected without a prompt. Focus a non-file editor that does not identify a repository and rerun; expected result: a repository picker appears, and the selected repository determines the panel title.
- [ ] **No repository:** Open an empty non-Git folder and run the command. Expected result: no panel opens and VS Code shows an error that no open Git repository was found.
- [ ] **Detached HEAD:** Check out a commit directly in a disposable repository and run the command. Expected result: no panel opens and VS Code reports that the repository is not on a local branch.
- [ ] **Missing base:** Use a disposable repository whose branches do not include the configured base, `main`, `master`, `origin/main`, or `origin/master`, then run the command. Expected result: no panel opens and the message tells the reviewer to configure `branchDiffReview.defaultBaseBranch`.
- [ ] **Keyboard behavior:** When the repository picker appears, use arrow keys and Enter to select a repository, then use Escape on a second run. Expected result: Enter opens the correctly titled panel; Escape cancels without opening a new panel or showing an error.
- [ ] **Existing panel:** Run the command, change to another local branch, and run it again. Expected result: the existing panel is revealed and its title updates to the new `<current> into <base>` comparison.
