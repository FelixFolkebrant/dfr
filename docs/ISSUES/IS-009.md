# Issue

### What?

IS-009: Add manual refresh to the Branch Diff sidebar.

### Acceptance criteria

- [x] The Branch Diff view title exposes a keyboard-accessible **Refresh** action.
- [x] Refresh re-discovers the active repository, current branch, and available refs before loading a comparison.
- [x] The selected base and compare refs remain selected when both still exist.
- [x] A missing selected ref resets both refs to the refreshed default base and current branch.
- [x] Refresh recomputes the merge base, file list, statuses, and line totals through the existing comparison loader.
- [x] Refresh clears the selected file, closes Branch Diff Review diff tabs, and ignores superseded comparison and file requests.
- [x] Existing loading, empty, and comparison error states are reused.
- [x] Repository discovery failures show an actionable VS Code error without replacing the last usable sidebar state.
- [x] Focused tests and all repository checks pass.

### Notes

- Refresh is manual. Automatic Git-state subscriptions, polling, caching, session persistence, and per-file refresh remain out of scope.
- If no review is active, Refresh starts the refreshed default comparison.
- There are no differences from the IS-009 plan.

# Issue recap

# What has been built

The Branch Diff view title now has a native refresh action. It re-discovers the active repository, current branch, available refs, and default base in the extension host, then reloads the merge-base comparison.

Valid selected refs survive refresh as a pair. If either ref disappeared, both reset coherently to the refreshed default base and current branch. Refresh reuses the existing loading, ready, empty, and error flow while invalidating older comparison and file requests, clearing file selection, and closing extension-owned native diff tabs.

## Manual testing

Run `pnpm build`, open this repository in VS Code, launch the **Run Branch Diff Review Extension** debug configuration, and open the **Branch Diff** activity-bar view in the Extension Development Host. Compared with the previous version, the Branch Diff view title now includes a **Refresh** icon that reloads repository and comparison state without reopening the review.

- [ ] **Create and edit:** In a disposable branch, commit a new file, click **Refresh**, then commit an edit to that file and refresh again. Expected result: the new file first appears as added with current line totals; after the edit, its status and totals update to match the refreshed merge-base comparison.
- [ ] **Rename and delete:** Commit a rename, refresh, then commit deletion of another compared file and refresh. Expected result: the renamed path and deleted status replace the previous file list entries, and the total files, additions, and deletions are recomputed.
- [ ] **Preserve refs:** Select non-default Base and Compare refs that still exist, commit a change, and refresh. Expected result: both selected refs remain selected while the comparison enters the existing loading state and then displays refreshed results.
- [ ] **Missing-ref fallback:** In a disposable repository, select non-default refs, then rename or delete either selected ref outside the Extension Development Host and refresh. Expected result: both selectors reset together to the newly discovered default base and current branch; no stale ref remains selected.
- [ ] **Selected diff cleanup:** Open a file from the sidebar so its native diff tab is visible, then refresh. Expected result: selection clears immediately after discovery, every Branch Diff Review diff tab closes, and an older in-flight file request cannot reopen one.
- [ ] **Loading and comparison errors:** Refresh a comparison large enough to show loading, then in a disposable repository create refs with no merge base and refresh that selection. Expected result: the normal loading view is used; the failure appears in the existing sidebar error state with refreshed selectors still usable.
- [ ] **Discovery error recovery:** With a usable comparison visible, close the repository folder or make Git repository discovery unavailable, then invoke **Branch Diff Review: Refresh Branch Diff Review** from the Command Palette. Expected result: VS Code reports an actionable discovery error and the last usable comparison remains unchanged.
- [ ] **Keyboard access:** Focus the Branch Diff view title toolbar using VS Code's standard keyboard navigation, focus **Refresh**, and activate it with Enter or Space. Expected result: the same refresh runs and focus remains usable without a pointer.
- [ ] **Empty and narrow states:** Select identical refs to produce an empty comparison, refresh, then narrow the sidebar below 240 px and refresh again. Expected result: the existing no-files state remains visible after loading; controls stack and truncate without horizontal overflow throughout refresh.
