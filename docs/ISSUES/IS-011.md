# Issue

### What?

IS-011: Refine commit review interactions and startup.

Keep Branch Diff Review active without a startup command, make commit review easier to enter from the aggregate scope, avoid presenting single-line commit messages as expandable, and provide clear visual confirmation after copying a commit hash.

### Acceptance criteria

- [x] Commit navigation is circular: oldest through newest, then **All**, then oldest again.
- [x] From **All**, the next arrow selects the oldest commit and the previous arrow selects the newest commit.
- [x] **All** has no positional number; commit numbering appears only after selecting a commit.
- [x] A single-line commit message is displayed without a disclosure control.
- [x] A commit message with a body remains collapsible.
- [x] Commit messages appear without a redundant **Message** heading.
- [x] A selected commit's position appears before its selector at normal sidebar text size.
- [x] Copying a commit hash temporarily replaces the copy icon with a visually distinct confirmation state.
- [x] Branch Diff Review starts automatically when the extension activates, without requiring an open command.

### Notes

- Publishing is intentionally deferred while these interaction changes are evaluated.
- Navigation arrows are disabled only when the branch has no introduced commits.

# Issue recap

# What has been built

Branch Diff Review now discovers the repository and starts its comparison when the extension activates; the redundant open command has been removed while explicit refresh remains available. Commit navigation cycles from oldest through newest, then **All**, and back to oldest. Moving backward follows the reverse order. The aggregate scope remains unnumbered. Commit messages appear directly without a redundant heading. Messages containing only one line render as static text, while messages with bodies use the message row itself as their disclosure control. The selected commit position appears before the commit selector with increased visual emphasis. Successful hash copies temporarily show a check mark with active-selection styling.

### Architectural alignment

| Area | Implementation |
| --- | --- |
| Commit navigation | Keeps sequence behavior in the existing webview component without changing extension state or protocol messages. |
| Message details | Determines disclosure availability from the existing commit message metadata. |
| Copy feedback | Uses existing VS Code theme tokens and the existing transient copy state. |
| Extension activation | Starts repository discovery after registering the sidebar provider and retains the existing refresh command. |

## Manual testing

Run `pnpm build`, launch the **Run Branch Diff Review Extension** debug configuration in a Git repository with multiple introduced commits, and open the **Branch Diff** activity-bar view in the Extension Development Host.

- [ ] **Automatic startup:** Without running a command, open **Branch Diff** and confirm the current repository comparison is already loading or visible. Confirm **Open Branch Diff Review** is absent from the command palette and the title-bar refresh action still reloads the comparison.
- [ ] **Circular navigation:** Select **All** and confirm no positional number is visible. Press the right arrow and confirm the oldest commit is selected with `1/N` visible. Press the left arrow and confirm navigation returns to unnumbered **All**. From **All**, press the left arrow and confirm the newest commit is selected with `N/N` visible; press the right arrow and confirm navigation returns to **All**.
- [ ] **Empty navigation:** Review a branch with no introduced commits and confirm both arrows are disabled.
- [ ] **Commit position:** Select a commit and confirm its `N/N` position appears to the left of the commit selector at a larger, readable size. Return to **All** and confirm the position disappears.
- [ ] **Single-line message:** Select a commit whose full message is one line. Confirm the message appears without a heading or chevron and cannot be expanded or collapsed.
- [ ] **Multiline message:** Select a commit with a subject and body. Confirm its subject row has a chevron but no separate heading, and activating the row reveals the full body.
- [ ] **Copy feedback:** Select a commit and activate the copy-hash button. Confirm its copy icon immediately changes to a check mark with a distinct background and success color, then returns to the copy icon after roughly 1.5 seconds. Paste elsewhere and confirm the full hash was copied.
- [ ] **Keyboard and narrow layout:** Repeat navigation, message disclosure, and hash copying using the keyboard at a sidebar width below 240 px. Confirm focus remains visible and the controls do not introduce horizontal scrolling.
