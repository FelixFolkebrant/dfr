# Issue

### What?

IS-008: Redesign branch selection and changed-file navigation.

Replace the constrained sidebar controls and third-party tree with a fully styleable branch comparison header and a GitHub-style changed-file tree that communicates file status and line counts without file-type icons.

### Acceptance criteria

- [x] Base and compare branches use custom webview comboboxes whose trigger and open list are controlled by the sidebar stylesheet.
- [x] Both branch selectors mark the current branch with `•` and support mouse and keyboard selection.
- [x] Changed paths are grouped into expandable folders without showing file-type or file-icon-theme icons.
- [x] Added, modified, deleted, renamed, and unknown files have distinct status-only symbols and theme-aware colors.
- [x] Available addition and deletion totals are independently colored and aligned at the right edge of each file row; binary files show a binary marker.
- [x] File selection continues to open the selected comparison in VS Code's built-in diff editor.
- [x] Loading, empty, error, selected, narrow-sidebar, focus, and keyboard states remain usable.
- [x] `@pierre/trees` and its transitive packages are removed.

### Notes

- The existing Git comparison state, webview protocol, validation, and native diff editor are retained. This issue changes only sidebar presentation and local tree state.
- VS Code file icon themes are intentionally out of scope because the redesigned rows use Git status symbols rather than file-type icons.
- Revision `/1` replaces the native TreeView direction from IS-008/0. Native rows could inherit user file icons, but could not meet the required branch-selector CSS and independently styled right-aligned metadata.

# What has been built

The Branch Diff sidebar now presents base and compare branches as a compact comparison header with custom React comboboxes. Their triggers, dropdown lists, active options, selected options, focus rings, current-branch markers, dimensions, and responsive layout are all owned by the sidebar stylesheet rather than browser-native select rendering.

The changed-file area now uses a local tree model and renderer. Paths are grouped and sorted into expandable folders, folders begin expanded, and file rows use only Git status symbols: plus for added, dot for modified, minus for deleted, directional arrows for renamed, and a fallback question mark for unknown states. Symbols inherit VS Code Git decoration colors. Addition and deletion counts occupy a dedicated trailing lane with independent colors and tabular numerals, while binary files show a text marker.

The tree implements roving focus and standard tree navigation for arrow keys, Home, End, Enter, and Space. The branch listboxes support arrows, Home, End, Enter, Space, Escape, Tab, pointer selection, and outside-click dismissal. Existing file-selection messages still drive the native VS Code diff editor.

Sidebar components are organized by responsibility: the top-level sidebar only coordinates extension state and messages, while branch comparison, combobox options, comparison status, changed-file sections, tree navigation, row presentation, and icons live in focused components under `webview/sidebar/components`.

### Architectural alignment

| Area | Result |
| --- | --- |
| Git comparison and line-count backend | Reused unchanged |
| Branch selector presentation | Custom accessible webview comboboxes |
| Changed-file presentation | Local React tree with status-only icons |
| Selected-file diff | Existing native VS Code diff editor |
| File icon themes | Intentionally not used |
| `@pierre/trees` | Removed |

### What is left

Search, filtering, viewed-file state, all-files review, and commit-by-commit review remain later work. Automated browser or extension-host interaction tests can be added if sidebar behavior grows beyond the current focused components; this issue covers the pure path-grouping and expansion model with unit tests and records the interaction checklist below for reviewer confirmation.

## Manual testing

Run `pnpm build`, open this repository in VS Code, launch the **Run Branch Diff Review Extension** debug configuration, and run **Branch Diff Review: Open Branch Diff Review** in the Extension Development Host. Compared with the previous sidebar, the branch controls and changed-file rows are completely restyled, file-type icons are absent, and Git status plus line totals are the primary row signals.

- [ ] **Initial comparison:** Open the Branch Diff sidebar on a branch with changes. Expected result: Base and Compare appear side by side above a one-line summary; the current branch has a `•`; folders start expanded; every file has a status symbol but no file-type icon; additions and deletions align at the right edge in separate colors.
- [ ] **File states and selection:** Review a comparison containing added, modified, deleted, and renamed text files plus a binary file, then click each text file. Expected result: plus, dot, minus, and rename symbols are visibly distinct and use their Git theme colors; zero counts are omitted; the binary row says `Binary`; selecting a text row highlights it and opens the correct native diff.
- [ ] **Branch selection:** Open each branch selector, move through its list, and choose another valid branch. Expected result: the entire dropdown uses the custom sidebar styling, the selected option has a check mark, the comparison enters loading state, then the summary and tree are replaced with the selected comparison and no stale file remains selected.
- [ ] **Empty and error states:** Select the same branch for Base and Compare, then exercise a Git comparison failure if a disposable invalid ref is available. Expected result: an empty comparison says no files changed and shows zero totals; a failed comparison displays its actionable error while both selectors remain available for recovery.
- [ ] **Keyboard behavior:** Tab to a branch trigger; use Arrow keys, Home, End, Enter, Space, and Escape in the dropdown. Tab to the tree; use Up/Down to move, Right/Left to expand or collapse and move to parents or children, and Enter/Space to select files. Expected result: focus is always visible, only one tree row is in the tab order, and every operation works without a pointer.
- [ ] **Responsive behavior:** Narrow the sidebar below 240 px. Expected result: Base and Compare stack vertically, branch names and file names truncate instead of forcing horizontal page overflow, and the trailing line counts remain visible.
