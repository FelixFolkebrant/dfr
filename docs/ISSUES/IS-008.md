# Issue

### What?

IS-008: Consolidate review navigation in one native Branch Diff view.

This issue replaces the separate branch webview and changed-file view with one compact native VS Code Tree View. Base and Compare open native Quick Picks, the summary occupies one row, changed files follow immediately with theme-aware Git status colors and badges, and GitHub-style added/removed counts remain visible.

### Acceptance criteria

- [x] One contributed **Branch Diff** view contains branch controls, summary, and changed files without a second view header.
- [x] Base and Compare occupy one native row each and open native Quick Picks.
- [x] The comparison summary occupies one row and shows file, addition, and deletion totals.
- [x] Changed files render directly below the summary and remain grouped by folder.
- [x] File rows use file-type icons plus theme-aware A/M/D/R status colors and badges.
- [x] File rows show GitHub-style `+added -removed` indicators or binary metadata.
- [x] Clicking a file validates its comparison ID and path before opening the native diff editor.
- [x] Loading, empty, and comparison-error states appear in the native view.
- [x] Branch changes replace the changed files and invalidate stale selections.
- [x] Native focus, keyboard navigation, folder expansion, collapse-all, and narrow-sidebar behavior require no custom implementation.
- [x] The remaining sidebar webview, React/Tailwind build path, third-party package dependencies, and lockfile entries are removed.
- [x] The product specification describes the native VS Code explorer architecture.

### Notes

- The existing controller remains the source of comparison state and validates every selected file before requesting content.

- Search, filtering, and viewed state remain out of scope.

# What has been built

The complete review navigator now occupies one native **Branch Diff** view. Base and Compare are compact command rows that open native Quick Picks, the active branch keeps its `•` marker, and a one-line summary shows changed-file and line totals. Changed paths follow immediately in expandable folders, so there is no second view header or independently scrolling branch panel.

File rows use the user's file icon theme and VS Code's Git decoration colors for added, modified, deleted, and renamed states. Native A/M/D/R badges mirror GitHub and GitLab status treatment, while `+added -removed` counts or `Binary` remain visible beside each path. VS Code supplies focus, keyboard navigation, scrolling, accessibility, and collapse-all behavior.

Clicking a file calls an internal command with the active comparison ID and path; the existing controller rejects stale or unknown selections before lazily loading content into VS Code's native diff editor. The former sidebar webview, React/Tailwind dependencies, webview build script, message protocol, and third-party tree integration are removed.

### Architectural alignment

| Area | IS-008 outcome |
| --- | --- |
| Complete sidebar navigation | One native VS Code Tree View |
| Branch selectors | Compact rows with native Quick Picks |
| Totals | One native summary row |
| File presentation | File icons, Git status colors/badges, and `+N -N` counts |
| Selection validation and diff loading | Existing extension-host controller retained |
| Webview and third-party UI dependencies | Removed |
| Search, filtering, and viewed state | Deferred |

### What is left

Later issues can add search, filtering, or viewed state if usage demonstrates a need. File navigation, accessibility, folder interaction, and theme colors remain native VS Code responsibilities.
