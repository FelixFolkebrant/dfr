# Issue

### What?

IS-015: Confirm copied commit hashes and simplify the sidebar details panel.

Show a temporary checkmark after a reviewer copies a selected commit hash. Replace issue-linked Markdown document discovery and opening with a single collapsible Message section that displays the selected commit's complete Git message.

### Acceptance criteria

- [x] Copying a selected commit hash changes the Copy hash icon to a checkmark for one second.
- [x] The button's accessible label and tooltip report that the hash was copied while the checkmark is visible.
- [x] The sidebar no longer discovers, lists, or opens Markdown or other issue-related documents.
- [x] Review metadata and sidebar messages no longer contain document-related state or commands.
- [x] A selected commit displays its complete Git message beneath a collapsible Message heading.
- [x] The Message heading uses the former Docs disclosure appearance and starts expanded.
- [x] Activating an open branch, commit, or history dropdown closes it.
- [x] Refresh resets the review branch to the repository's current Git branch.

### Confirmation

#### Automated checks

- `pnpm check` on 2026-08-03: passed extension and webview TypeScript checks, Biome, all 42 unit tests, and production builds.
- `git diff --check` on 2026-08-03: passed with no whitespace errors.

#### Manual testing

Run `pnpm build`, press `F5` in VS Code, open DFR from the Activity Bar, and compare a branch containing at least one commit with a multi-line message.

- [ ] **Message section:** Select the commit and confirm a Message heading is visible and initially expanded. Confirm its full subject and body appear beneath the heading. Activate Message with Enter or Space, then confirm the text hides and the chevron reflects the collapsed state; activate it again and confirm the message returns.
- [ ] **Copy confirmation:** With an individual commit selected, activate Copy hash using the pointer, Enter, or Space. Confirm the full SHA is copied to the clipboard, the icon changes to a checkmark immediately, and it returns to the copy icon after about one second.
- [ ] **No document panel:** Compare a branch that changes a Markdown file. Confirm there is no Docs heading or related-document link, and that the Markdown file remains available only as a normal changed file in the Changed files section.
- [ ] **Empty and loading states:** Select All changes, then switch comparison branches or refresh. Confirm the copy button is disabled unless an individual commit is selected, and that no Message section appears while no commit is selected or the comparison is loading.
- [ ] **Narrow sidebar and keyboard:** Narrow the DFR sidebar, Tab to Message and Copy hash, and operate both with Enter or Space. Confirm Message text wraps without horizontal overflow and the checkmark feedback remains visible.
- [ ] **Dropdown toggle:** Open each branch, commit, and history dropdown, then activate the same trigger again. Confirm each dropdown closes instead of reopening or changing its selection.
- [ ] **Refresh review branch:** Select a review branch other than the repository's current Git branch, then activate DFR: Refresh. Confirm the review branch changes to the current Git branch and its changed files and commits are shown.

### Notes

- The removed feature was DFR's issue-linked document discovery and quick-open path. Markdown files are still ordinary repository files and can be reviewed through Changed files.
- The repository issue record is retained because the project workflow requires it for review and pull-request publishing.
