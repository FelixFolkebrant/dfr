# Issue

### What?

IS-003: Compute merge-base comparison summaries.

This issue adds the extension-host Git comparison service needed to describe what the current branch introduces relative to its resolved base branch. It resolves the merge base, reports changed files with status and rename information, and combines numstat output into file and total addition/deletion counts without loading patch bodies or sending comparison state to a webview.

### Acceptance criteria

- [x] Stable comparison input, summary, file-status, and file-summary types are defined behind the internal Git backend boundary.
- [x] Comparisons use `git merge-base <base> <head>` followed by diffs from the merge base to the head ref.
- [x] Changed-file summaries parse added, modified, deleted, renamed, binary, and unknown Git results.
- [x] Rename summaries retain both the old and new paths.
- [x] Per-file and total addition/deletion counts are combined with file status results.
- [x] Git commands continue to use argument arrays without shell interpolation.
- [x] Summary and parser failures produce actionable errors.
- [x] Patch loading and webview comparison state remain out of scope.
- [x] Focused automated tests and all repository checks pass.

### Notes

- The comparison service uses `--find-renames`, machine-readable NUL-delimited name-status output, and NUL-delimited numstat output.
- Binary is represented independently from change status so an added, modified, deleted, or renamed file can also be binary.
- Loading one selected file patch is planned for IS-004.

# What has been built

The extension host now exposes comparison-summary types and a `getComparisonSummary` method through the internal Git backend. The native backend delegates this work to a focused diff service that first resolves the merge base and then runs parallel, machine-readable name-status and numstat diffs from that commit to the selected head ref.

The parser preserves added, modified, deleted, renamed, and unknown statuses, retains both rename paths, and marks binary files independently from their change status. Numeric per-file counts are combined into comparison totals, while binary files omit unavailable line counts. Git failures and malformed output include the affected refs or comparison in the reported error.

The repository now uses Node's built-in test runner for focused backend tests, and `pnpm check` includes those tests.
