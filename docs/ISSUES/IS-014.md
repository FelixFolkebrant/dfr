# Issue

### What?

IS-014: Add merged-branch history navigation and reorganize the review controls.

Allow reviewers to browse first-parent merges on the comparison base, inspect the complete change introduced by each merge, and step through the commits from the merged branch. Present branch and commit selection as connected layers above the review toolbar, and emphasize commit number and message while keeping change statistics secondary.

### Acceptance criteria

- [x] A History button is displayed next to the comparison settings button.
- [x] Opening History displays a slim, subtly darker merged-branch panel above the review toolbar without a redundant History heading.
- [x] History contains branches merged through first-parent merge commits on the selected comparison base.
- [x] History is ordered newest-first, with merge titles emphasized and branch names shown as secondary text.
- [x] Every merged branch in the expanded History selector shows its commit count, additions, and deletions without a redundant combined line total.
- [x] The compact selected-branch control shows only the branch name and merge title.
- [x] The commit selector sits immediately below History and above the review toolbar with layered backgrounds.
- [x] The commit menu is ordered newest-first and shows each commit's number, message, changed files, additions, and deletions.
- [x] Each commit uses a two-row card: message above; number, changed files, additions, and deletions below.
- [x] A reviewer can move up toward newer branches and the current review or down toward older branches.
- [x] Selecting a merged branch shows the full mainline change introduced by its merge.
- [x] A reviewer can select and step through the individual commits from the selected merged branch.
- [x] Closing History or choosing Current review closes History and restores the previously selected comparison branches.
- [x] The selected commit control shows its number and message prominently, with changed files, additions, and deletions as secondary details.
- [x] The aggregate commit control shows the reviewed branch name instead of **All changes**.
- [x] The aggregate entry in the commit menu omits the **All changes** title and shows its statistics on one row.
- [x] The aggregate entry retains a subdued **All** label to the left of its statistics.
- [x] A **Copy hash** toolbar button beside History copies the selected commit's full hash.
- [x] Commit statistics are right-aligned and commit ordinals are visually secondary.
- [x] Commit and history selectors omit dropdown icons, and the compact history control shows only the branch name.
- [x] History selectors omit graph markers and rails, with changed-file statistics right-aligned.
- [x] History entries place the branch name to the left of the changed-file statistics on one metadata row.
- [x] Narrow history dropdowns hide the branch name while retaining the merge title and changed-file statistics.
- [x] At narrow selector widths, changed files, additions, and deletions move together to their own row below the commit number.
- [x] Selecting a changed file while reviewing an individual commit opens that commit's file diff.

### Notes

- History follows first-parent merge commits on the selected comparison base. Squash and rebase merges do not retain a merged branch boundary and therefore cannot appear as branch history entries.
- The full historical branch scope compares a merge commit with its first parent so the view reflects the actual change to the base branch. Individual commit scopes are loaded from the merge commit's second-parent branch history.
- Branch names are recovered from common GitHub pull-request and Git branch merge subjects because deleted source refs are not guaranteed to remain available locally.
- History statistics count commits reachable from the merged head but not its first parent. Additions and deletions compare the merge commit with its first parent, so they include merge-resolution changes; binary files do not contribute line statistics.
- Commit statistics come from each commit's Git numstat. Binary files count as changed files but do not contribute additions or deletions.
