# Issue

### What?

IS-012: Add tree, flattened, and contextual views for changed files.

Let reviewers choose between a file-first flattened list, a changed-file tree, and a repository-wide contextual tree that locates changes without competing with them visually.

### Acceptance criteria

- [x] Changed files default to a flattened, file-first list.
- [x] Flattened rows group files beneath compact, collapsible parent-directory rows without visually nesting the files.
- [x] Three icon buttons beside the Changes subtitle switch between tree, flattened, and contextual views.
- [x] The tree view retains collapsible folders and keyboard tree navigation.
- [x] The contextual view shows tracked repository folders and files, expands changed-file ancestors, and dims everything except changed files.
- [x] Folder rows have folder icons.
- [x] Collapsed folders summarize their changed-file count, additions, and deletions; their labels, icons, and rows remain fully emphasized.
- [x] Tree icons use compact spacing, with changed-file status icons aligned to their parent folder-icon guide.
- [x] Contextual changed-file rows have subtle status-colored backgrounds: green for changes, stronger green for additions, and red for deletions.
- [x] Branch selection is available in comparison settings, opened from a cog beside commit navigation.

### Notes

- Contextual paths come from tracked files at the selected comparison head; ignored and untracked files are not included.
- The display choice is local webview state and resets when the sidebar reloads.

# Issue recap

# What has been built

The changed-file area now has a Changes subtitle with three compact view buttons. It supports a default flattened list, a changed-file tree, and a contextual tree built from the selected Git revision. Contextual mode expands the path to each change and dims unchanged files and folders. Folder rows have open and closed folder icons; when collapsed, folders summarize changed files and line totals, and changed folders retain normal emphasis.

### Architectural alignment

The display mode remains UI-only state. The Git backend supplies tracked paths for the selected head revision, while shared tree helpers combine those paths with diff metadata into deterministic contextual rows.

### What is left

Persisting the display preference is outside this issue.

## Manual testing

Run the extension with the VS Code `Run Extension` launch configuration and open the Branch Diff sidebar with a branch containing changed files.

- [ ] **Initial appearance:** Confirm the Changes subtitle and three adjacent view icons appear above a flattened list grouped by parent directory. Confirm each directory has its own compact, muted row with no folder icon and a right-aligned fold chevron. Confirm files remain aligned with root files instead of appearing nested. Collapse and expand each directory and confirm only that exact group is affected. Confirm long paths truncate without pushing diff totals offscreen, root files remain ungrouped, and the flattened icon has active styling with a descriptive tooltip.
- [ ] **Tree view:** Select **Tree** and confirm only changed files appear beneath collapsible folders.
- [ ] **Folder display:** In Tree and Contextual views, confirm folders have folder icons that change when expanded or collapsed. Confirm chevrons and folder icons use compact spacing and changed-file `+` or `−` icons align vertically with their parent folder icon. Collapse a folder containing multiple changed files and confirm its row shows the changed-file count plus summed additions and deletions (for example, `2 +200 -100`).
- [ ] **Contextual view:** Select **Contextual** and confirm tracked repository folders and files appear, changed-file ancestors are expanded, and unchanged files and folders without visible collapsed-change totals are dimmed. Confirm changed-file rows have a very light green background, added files have a stronger green background, and deleted files have a red background; confirm these tints do not appear in Tree or Flattened views. Select a changed file and confirm the normal selection background takes precedence. Collapse a changed-file ancestor and confirm its complete row, including the folder icon and label, is no longer dimmed while its totals are visible.
- [ ] **File interaction:** In every view, select a changed file and confirm its diff opens and its row receives selected styling. In contextual mode, confirm selecting an unchanged file does not open a diff.
- [ ] **Keyboard behavior:** Tab through the three view buttons and activate each with Enter or Space. In flattened mode, use Up, Down, Home, and End to move through files. In tree and contextual modes, also use Left and Right to collapse, expand, and enter folders.
- [ ] **Scope changes:** Select a commit and then All; confirm contextual mode refreshes to represent files tracked at that scope’s head revision.
- [ ] **Comparison settings:** Confirm the branch selector is absent from the review view. Open the cog beside the previous and next commit buttons and confirm **Review branch**, **Compare with**, and commit naming controls appear. Change each branch, confirm the comparison refreshes, then close settings with the same cog and confirm the review returns with the selection preserved. Repeat using keyboard navigation and Enter or Space.
- [ ] **Empty state:** Compare branches with no changed files and confirm “No files changed in this comparison.” remains visible.
